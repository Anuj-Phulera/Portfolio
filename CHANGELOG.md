# Changelog

Dated by phase, newest first. This records what changed, not how impressive it was.

## Phase 2 — Motion studio

- Working studio: seven stages (cut pacing, word reveal, pointer depth, reveal-once,
  scroll readout, view transitions, consent-gated sound).
- Lenis, anime.js and GSAP integrated; 25 tests including a jsdom integration mount.
- Reduced motion implemented as a real alternate path, switchable at runtime.
- Production bundle measured at 44 KB gzipped with all three libraries.

## Phase 1 — Preparation package

- Nine project audits graded against source, not README claims.
- Claims ledger: 34 entries, validator, generated report, wording guide.
- Attribution policy naming Aarav Choudhary's hardware contribution to VERDE.
- Three creative directions with measured palettes and a risk register.
- Storyboards for openings, middle, endings, and six interaction specs.
- Motion lab (dependency-free) from which the studio was built.
- Quality toolkit: contrast checker, documentation audit, release gate.

## Phase 0 — Discovery

- Verified public record, corrected assumptions, established the north star.
- Withdrew an inferred school/board/location assumption rather than keeping a tidy story.

## Phase 6 — Verification that can be wrong

- A browser suite that runs in CI, because the build machine has no browser:
  routes, layout, axe in a real engine, keyboard, the three instruments, reduced
  motion and print, plus screenshots as an artifact.
- The suite found real defects on its first three runs: the mode engine gave no
  feedback until the pointer left, the edge marker sat at 3.9:1, and a code
  block became a scrollable region with no keyboard entry point on a phone.
- axe-core and html-validate also run offline; between them they found 24 inline
  styles and a lowercase doctype, and the bar heights moved into the stylesheet.
- External link checking: it found **eight of nine repository links returning
  404**. The entries pointed at the newer account; the work is on the older one.
- The survey count was re-derived: the file holds **255 records from 254
  respondents**, not 261. The original figure was a line count of a CSV whose
  free-text answers contain line breaks. CLM-035 records the correction; CLM-016
  stays as written.
- The survey now appears as aggregates and four charts: 1.3 KB of counts and
  means, with tests that fail if an identifier ever reaches the output.

## Phase 5 — Ship readiness

- Subpath deploys: the site now builds correctly under `/Portfolio/`, with the
  prefix applied once to finished HTML and canonical URLs derived from an origin.
- A route manifest: the renderer, the sitemap and the tests read the same list,
  so a page cannot exist in one and be missing from another.
- Generated `sitemap.xml` and `robots.txt`; `noindex` on the error page.
- Structured data for the person, the site and each entry — no ratings, no
  counts, nothing the copy does not already say.
- A falsifier block: every entry now names the observation that would make it
  false.
- Contract tests that compare the manifest against the built files in both
  directions.
- CI: one workflow runs the full gate on every push; a second builds and deploys
  to GitHub Pages (needs one manual switch to enable).
- The browser pass is written down as a checklist, because no browser exists on
  the machine that built this.

## Phase 4 — The portfolio site

- Direction C built: a bench of six entries and three operable instruments, with
  the receipt discipline of Direction A and the held-frame pacing of Direction B.
- Twelve static pages generated by a Node script; no framework, no router, no
  hydration. JavaScript is one 1.7 KB island bundle for the three instruments.
- The claims gate: content cites ledger ids, and the build refuses to emit a
  blocked claim. It failed on its own author's first run, which was the point.
- Measured: 81.4 KB transfer for the whole site, largest page 4.9 KB gzipped.
- New checks: internal link and anchor checking for built HTML, a directory-wide
  accessibility pass, and a site transfer budget.
- Separate documents for the site's decisions, content policy, accessibility
  limits and performance method.

## Phase 3 — Studio expansion and repository organisation

- The studio grew from seven stages to ten: native scroll-driven scenes, a drag
  dial with keyboard equivalents, and figures that cannot render without a
  source and a commit.
- Registry with integrity assertions, capability probes, and a session read-out.
- Four quality tools joined the release gate: static accessibility, bundle
  budget, markdown link checking, and a documentation index.
- Repository structure: `REPO-MAP.md`, folder READMEs, ADRs, this changelog.
